## Findings

### OVR-VER1 — Major — Port-0 mode bypasses the configured CONNECT-port allowlist

- **Owner:** `P4-G1`
- **Source items:** `W260914RUZU-REQ2@R1`, `W260914RUZU-REQ6@R1`, `W260914RUZU-REQ9@R1`, `W260914RUZU-DES1`, `W260914RUZU-DES2`, `W260914RUZU-DES5`, `W260914RUZU-DES7`, `S3`, `S12`, `S17`, `V2`, `V6`, `V16`, `V20`
- **Evidence:** `src/config.rs:403-419` permits arbitrary configured ports whenever the proxy listener uses port 0. More importantly, `src/proxy.rs:176-185` checks `if !allowed_ports.contains(&port) && !allow_ephemeral_loopback_ports`, so when the port-0 flag is true every nonzero CONNECT destination port is accepted, including ports not listed in `allowed_ports`. The mode is production code selected solely by user TOML (`listen = "127.0.0.1:0"`), not a test-only compile/runtime authorization. Existing `src/config.rs:764-782` proves only that one arbitrary configured port loads; it does not prove other ports remain rejected.
- **Impact:** A user configuration intended to allow one dynamically assigned test-origin port becomes a loopback proxy to every destination port. This violates the configured safe-port boundary and the remediation requirement to preserve production security constraints.
- **Required resolution:** Keep the scoped ability to configure a nonstandard explicit port for race-free local integration if needed, but always require the CONNECT authority port to be present in the validated `allowed_ports` set. Do not use listener port 0 as a blanket parser bypass.
- **Required proof:** Add config/parser/runtime tests showing ephemeral mode accepts the explicitly configured dynamic port and rejects at least one other unconfigured port with exact `ProxyError::PortNotAllowed`/HTTP 403; run affected integration tests and all overall Rust checks.

### OVR-VER2 — Major — Required DoH bootstrap rule is not documented

- **Owner:** `P4-G2`

- **Evidence:** `w260914ruzu-requirements.md:308` requires a documented bootstrap rule that does not depend on resolving selected blocked domains. `README.md` contains no bootstrap guidance, and `config.example.toml:6-8` only supplies `https://1.1.1.1/dns-query` without stating the general rule. `src/config.rs:422-433` accepts any HTTPS hostname, so operators can configure an upstream hostname whose bootstrap depends on normal OS DNS or overlaps selected blocked domains. The V20 test at `src/config.rs:820-857` does not assert bootstrap documentation.
- **Impact:** The shipped operating contract omits an explicit acceptance criterion and can lead users to choose a DoH endpoint that cannot be reached independently of the DNS path the tool is intended to avoid.
- **Required resolution:** Document that the DoH endpoint host must be bootstrap-reachable without resolving a configured selected/blocked domain; recommend a literal-IP HTTPS endpoint with a certificate valid for that endpoint or another independently resolvable non-target host. Keep certificate authentication mandatory.
- **Required proof:** Extend the V20 README/config consistency assertion for the bootstrap rule, run the focused production `Config::load` consistency test, and rerun all overall Rust checks.
